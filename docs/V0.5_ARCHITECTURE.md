# v0.5 System / Software Architecture

## System topology

```text
Repository A                     Repository B
  .stellar/project.json           .stellar/project.json
          |                                |
          +---------------+----------------+
                          |
                  Global Registry
                    registry.db
                          |
        +-----------------+------------------+
        |                                    |
  Project A index.db                    Project B index.db
        |                                    |
        +-----------------+------------------+
                          |
                Stellar Global Service
              /           |            \
           CLI         HTTP/UI          MCP
```

Only one HTTP/MCP service is required. Each project keeps an independent index DB.

## Access path

```text
UI / MCP / CLI request
        |
        v
resolve project UUID/name/path
        |
        v
check registered root + project UUID
        |
        +---- unavailable ---> MISSING / ORPHANED
        |
        v
mark ACTIVE
        |
        v
lazy sync
  Git clean fast-path
  or incremental scanner/parser
        |
        v
query project index.db
```

No source content is copied into global storage.

## Lifecycle

```text
                     recent access
             +---------------------------+
             |                           v
          IDLE <---------------------- ACTIVE
           |                           |
 root unavailable                     | inactivity
           v                           |
        MISSING -----------------------+
           |
   grace period elapsed
           v
       ORPHANED
```

`MISSING` and `ORPHANED` preserve `index.db`.

## Move handling

```text
Old path disappears
       |
registry -> MISSING

Repo appears at another path with same .stellar project UUID
       |
first StellarCode command at new location
       |
registerProject(UUID,newPath)
       |
registry path updated
index.db reused
       |
ACTIVE
```

StellarCode intentionally does not crawl the filesystem to discover the new location.

## Main modules

```text
src/storage/registry.js
  registry migration, reconciliation, lifecycle, summaries, GC

src/core/global-runtime.js
  project selector/path resolution and availability checks

src/web/global-server.js
  one global HTTP service and lazy sync boundary

src/mcp/server.js
  global project discovery + project-aware MCP tools

src/indexer/sync.js
  deterministic incremental indexing + registry last-indexed state
```

## Safety constraints

- No Home watcher.
- No Home recursive scan.
- No automatic index deletion.
- Missing root is not interpreted as permanent deletion.
- UUID, not filesystem path, is project identity.
- Cache and durable index have different retention semantics.
