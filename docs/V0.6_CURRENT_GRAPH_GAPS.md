# v0.6 current graph gaps (diagnosis before any parser or index change)

This document records what the v0.5.6 index can and cannot do, as the base for v0.6. Nothing in `src/indexer` or `src/query` was changed while writing it.

**Base.** Branch `feat/v0.6-semantic-behavior-graph`, cut from `main` (`565f29e`, v0.5.6). It adds two commits on top:

- the benchmark attribution fix
- a port of the v0.5.9 model-turn telemetry (cherry-picked; no v0.5.7 or v0.5.8 ranking code)

## How the index works today

| Stage | File | What it produces |
|---|---|---|
| Parse | `src/indexer/parser.js` | **Regex over masked text**: comments and strings are blanked, so line and column offsets are preserved. It emits symbols and import facts per file. There is no AST. |
| Store | `src/storage/db.js` | `symbols` (name, qualified name, kind, line range, exported), `unresolved_imports` (specifier plus a bindings JSON per file), and `edges` |
| Resolve | `src/indexer/sync.js` `rebuildEdges` | Rebuilt globally on every sync from the stored per-file facts. Only changed files are re-parsed. |
| Edges | | `contains` (file→symbol), `imports` (file→file), `tests` (test file→file) and `references` (file→imported symbol: confidence 0.9 for a value binding, 0.6 for a type-only binding) |
| Query | `src/query/query-service.js` `contextForTask` | Files are ranked lexically. A "used binding" is checked at query time by an identifier regex over the symbol body (`usesBinding`). Related evidence comes from `references` edges plus that regex check. |

The resolver already supports relative imports, `tsconfig`/`jsconfig` `paths` aliases, index files, and Python absolute and relative modules. Indexing is deterministic, uses zero tokens and stores no source bodies.

## Capability trace

| Capability | JS/TS | Python | Evidence in code |
|---|---|---|---|
| Imports (module → module) | **supported** | **supported** | `parseJsTs` imports and `resolveJSImport`; `parsePython` and `resolvePythonImport` |
| Import bindings and aliases (`{ a as b }`, default, namespace, `import type`) | **supported** | **partial**: `from m import a as b` keeps `a` and drops the local alias `b` | `parseJSImportBindings`; `parsePython` `split(/\s+as\s+/)[0]` |
| `require()` and dynamic `import()` | **partial**: module edge only, no bindings | n/a | `parseJsTs` second pass |
| References (who uses which symbol) | **partial**: file → imported symbol only. Usage inside a function is a query-time regex, not an indexed symbol → symbol relation. | **partial**: same; the binding name must match exactly | `rebuildEdges` `references`; `usesBinding` |
| Symbol ranges | **supported** for functions, classes, interfaces, type aliases, arrow-function constants and class methods. **Partial**: class-property arrow functions (`handle = () => {}`), object-literal methods and anonymous default exports have no symbol. | **supported** for classes, `def` and methods (indent-based) | `declarations`, `methodRe`; `pythonBlockEnd` |
| Direct calls of a local or imported function (`saveUser(x)`) | **unsupported** as an edge (only the regex check at query time) | **unsupported** | — |
| Member calls (`this.repo.save()`, `obj.method()`, `module.fn()`) | **unsupported** | **unsupported** | — |
| Receiver typing (field and parameter types) | **unsupported** | **unsupported** | — |
| Constructor assignments (`this.repo = repo`) and TS parameter properties | **unsupported**: `constructor` is just a method symbol | **unsupported** (`self.repo = repo`) | — |
| `implements` / `extends` | **unsupported**: the class regex captures only the name | **unsupported**: base classes are not recorded | `declarations[class]` |
| Re-exports (`export { x } from`, `export * from`, `export { x as y }`) | **unsupported**: not even a module edge, so a barrel `index.ts` is a dead end | **partial**: `from .a import x` inside `__init__.py` is an import, but it is not followed through to the original symbol | `parseJsTs` has no `export … from` pattern |
| Callback registration (`router.post('/x', handler)`, `on('evt', fn)`) | **unsupported** | **unsupported** | — |
| Python `self` fields | **unsupported** | **unsupported** | — |
| Graph direction in context output | **partial**: `relatedEvidence.direction` is `outgoing`, `incoming` or `internal`, but the relation is `imported-symbol` or `imported-by`, never a call | same | `contextForTask` |

## What agents did after the context arrived (exposed repositories, development only)

Source: v0.5.9 Stage 2 `pull` runs, repetition 1 (kc002-ota, goodjobshare, patentskill; 24 tasks). For each task I listed the tool calls made after `stellar context` and asked which missing relation would have answered them.

| Missing relation | Tasks where post-context calls looked for it | Example (paraphrased) |
|---|---|---|
| **Incoming callers or consumers** of a changed symbol (impact) | 7 / 24 | grep `emailVerificationRepo\.` across services; grep `fetchUtil`, `keywordFromQuerySelector`, `invoke_tool_off_loop`, `RateLimitDecision` |
| **Outgoing callees** across files (flow) | 5 / 24 | grep `createHybridEncryptedStream`, `postAuthGoogleApi`; read the next file in the chain |
| **Member calls on an imported singleton or instance** (`repo.method()`, `denylist.add()`) | 4 / 24, overlapping both rows above | `emailVerificationRepo.create(...)`, `tokenDenylist.isRevoked(...)` |
| **Registration** (route → handler) | 1 / 24 | "start at the request handler for POST /api/kc003/download" |
| Implementation of an interface or contract | 0 / 24 | — |
| Not a graph gap: a wrong top target or an excerpt too short (the agent re-reads the whole file) | 10 / 24 | navigation tasks that grep domain words; `cat -n` of a whole delivered file |

Readings:

- **Most graph-addressable exploration is direction-specific call and consumer reconstruction.** Impact tasks grep for uses of the changed symbol. Flow tasks grep for the next callee.
- **The most common unsupported pattern is a member call on an imported object.** Examples: `fooRepository.method()`, a module singleton, a service instance.
- **Implements edges were not what these agents searched for.** They are still in scope as a contract relation, but they are not the main driver.
- **About 40% of post-context exploration is not a graph gap.** It is ranking or excerpt sufficiency, and v0.6 does not claim to remove it. The pre-registered 40% target is therefore demanding: it requires semantic slices to remove nearly all of the graph-addressable exploration.

## Smallest architecture that closes the identified gaps

1. **Per-file call-site facts, extracted from the existing masked text.** For each call or callback argument, record:
   - the enclosing symbol and the callee expression shape (`name`, `recv.name`, `this.field.name`, `self.field.name`)
   - the line
   - identifier arguments, for registrations

   Also record, per file:
   - class heritage (`extends`/`implements`)
   - constructor field bindings (`this.x = param`, TS parameter properties, typed fields)
   - re-exports
   - Python import aliases
2. **Global resolution in `rebuildEdges`**, next to `references`. Resolution is deterministic (bindings, re-export chains, field types, unique members) and emits edges **only** when the resolution is unique. Ambiguity becomes a medium-confidence interface edge or no edge at all.
3. **A bounded semantic slice in `contextForTask` (compact)**, traversed by intent and direction. Source is deduplicated per range and the existing byte budget is kept.

No AST library, LSP or type checker is required for these patterns; see [V0.6_PARSER_DECISION.md](V0.6_PARSER_DECISION.md).
